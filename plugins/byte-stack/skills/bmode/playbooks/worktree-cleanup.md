### Worktree and simulator cleanup

**Delete only what is merged and clean. Uncommitted work belongs to the user.**

Not established in bphs-connect: a worktree audit or cleanup script, any `git worktree prune` step, and any iOS simulator use. Every simulator, `simctl` or `xcrun` mention is under `.claude/skills`: the `impeccable` design references (`xcrun simctl` only in `reference/ios.md`) and a `teach` list of lesson widgets. None is in `docs/`, `scripts/` or `.github/`. Skip the simulator half.

1. **Know where worktrees come from.** `implement-spec` gives each implementer subagent its own worktree on its own branch, and its last step cleans them all up. `scripts/claude-edit-hooks.ts` guards an edit in a worktree under `.claude/worktrees/` like one in the repo. No repo file lists them; git's own `git worktree list` shows each worktree, its checked-out branch or detached HEAD, and whether it is prunable.
2. **Judge merged by the PR, not by git.** A squash merge leaves a branch's commits off `main`. Read the issue number from the branch name (`<descriptor>/<action>-issue<N>-<description>`) and find that issue's PR with `gh pr list --search "<N>"` (`byte-gh-issue-claim`), then read it with `gh pr view <number>` (`docs/agents/issue-tracker.md`). An `implement-spec` implementer branch is done once its merger subagent has merged it into the integration branch.
3. **Never remove uncommitted work.** In each candidate, run `git status --porcelain`. If it prints anything, stop and show the user. Never discard the user's changes (`byte-gh-issue-claim`).
4. **Remove the clean, merged set.** Per path, run `git worktree remove <path>`. Git itself refuses a worktree with untracked files or modified tracked files unless `--force` is given, so leave `--force` off. Then delete the local branch as `docs/directives/git-and-prs.md` says: `git switch main`, `git pull`, then `git branch -D <branch>`. It takes `-D` because a squash merge leaves the branch's commits off `main`.
5. **Other local space.** `tmp/` is git-ignored scratch output of the `docs/verify` scripts: logs, scratch servers, browser profiles and their tools. `tmp/pr-body.md` may hold a PR body draft that `docs:stale` reads. `handoff/` is git-ignored, and the hook keeps only the newest three handoffs. `data/` is the git-ignored development database; the repo's way to clear it is `bun run db:seed --reset` with `bun run dev` stopped (`docs/how-to/develop-locally.md`), so do that only if the user asks. `qa-shots/` is git-ignored local screenshots and mocks that `DESIGN.md` names, and nothing in the repo says to delete them: ask first.

Production disk is not this playbook. On the VPS, the repo's disk step is "Clean up old images" in `docs/how-to/run-project.md` (`sudo docker image prune -f`). It never removes a volume or the image tagged `previous`. Step 2 there removes `bphs-connect:previous` only once an upgrade has run well for a while, and going back then needs a rebuild. The data lives in the Docker volume `bphs-connect-data`. Never run `docker compose down -v`, remove `bphs-connect-data` or prune volumes during an upgrade, and `docs/how-to/troubleshoot.md` says never to delete the data volume when a build runs out of space. Backups prune themselves (`scripts/backup-offbox.sh` by age, `scripts/staging.sh` keeps 3 pulled backups), and the repo gives no step for deleting production backups by hand. The `/data/pre-restore-*` folders are the one thing `troubleshoot.md` calls the operator's to delete, but `docs/how-to/restore-database.md` step 7 puts a `**Stop:**` line on it, and `docs/directives/production-safety.md` says an agent never runs such a step without the operator's go-ahead.

Guards: while a handoff is pending, handoff-guard refuses the main thread any `git` subcommand except `status`, `log`, `diff`, `add`, `commit`, `rev-parse`, `show`, `branch` and `check-ignore` (subagents are exempt). So `git worktree remove` waits until the handoff is written. The `git-guardrails-claude-code` skill lists `git branch -D` as blocked, but its script is not wired into `.claude/settings.json`.

**Reply:** the worktrees removed, the branches deleted, the space reclaimed, and one line for each one held back (uncommitted work, or PR not merged).
