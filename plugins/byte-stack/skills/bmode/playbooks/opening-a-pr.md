# Opening a pr

Use when: Prepare a tested change for pull request review.

Verify scope against the issue and run the repository checks. Run review-loop or the review process named by the repo. Use its PR template and Conventional Commit title where applicable. Resolve outstanding findings, confirm authorization to publish, then verify the PR base and head.

For repositories using the shared issue convention, name the branch `<descriptor>/<action>-issue<N>-<description>` and use its corresponding Conventional Commit type in the PR title. Check the base branch and head before publishing. Squash-merge only when authorized and consistent with the repository’s merge policy.
